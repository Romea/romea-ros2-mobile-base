# romea_mobile_base_hardware

## 1) Overview

`romea_mobile_base_hardware` provides reusable `ros2_control` hardware abstractions for ROMEA mobile bases.

It defines:

* architecture-specific hardware interfaces that expose the joints of a mobile base as `ros2_control` command and state interfaces;
* a generic `HardwareSystemInterface` base class used by robot-specific hardware packages;
* a small set of generic topic-based hardware plugins that exchange commands and feedback through `sensor_msgs/msg/JointState` messages.

This package does not implement the communication with a specific real robot. Robot packages such as `cinteo_hardware`, `adap2e_hardware`, `husky_hardware` or `scout_hardware` extend these classes and keep their platform-specific communication code in their own packages.

## 2) Hardware concept

In a complete robot bringup, the mobile base hardware plugin is declared in the `<ros2_control>` section of the robot URDF generated by the description package. The `controller_manager` loads this plugin, builds a `hardware_interface::HardwareInfo` object from the URDF content, and passes it to the hardware class during initialization.

The hardware layer then exports:

* command interfaces, where mobile base controllers write actuator commands;
* state interfaces, where mobile base controllers read actuator feedback.

`romea_mobile_base_hardware` handles the common part of this work: it reads the joint layout for the selected mobile base architecture, creates the corresponding steering, spinning or track joint handles, and exposes them to `ros2_control`.

Robot-specific hardware packages only have to implement the platform communication:

* connection and disconnection to the robot low-level controller;
* conversion from exported command interfaces to robot-specific commands;
* conversion from robot feedback to exported state interfaces;
* platform-specific initialization, shutdown and safety behavior.

## 3) Hardware interfaces

The package provides `HardwareInterface<mobile_base_architecture>` classes for the supported mobile base architectures.

These classes are not full `ros2_control` plugins by themselves. They are reusable C++ building blocks used by real hardware plugins, simulation plugins and generic bridge plugins.

Final real robot implementations can be found in the corresponding `<robot_name>_hardware` packages.

| Architecture | Hardware interface | Used by |

## 4) Generic Hardware Interfaces

### 4.1) Concept

`GenericHardwareSystemInterface` is a generic `hardware_interface::SystemInterface` built on top of the architecture-specific hardware interfaces.

It is useful for robots with closed low-level controllers, where direct actuator access is not available but a ROS 2-compatible bridge can exchange commands and feedback. It keeps the ROMEA controller stack unchanged: `controller_manager` loads a standard `ros2_control` hardware plugin, mobile base controllers write command interfaces and read state interfaces, and `GenericHardwareSystemInterface` translates these interfaces to the available communication mechanism.

### 4.2) Runtime behavior

At runtime, a `GenericHardwareSystemInterface`:

1. loads the `hardware_interface::HardwareInfo` generated from the robot description;
2. creates the architecture-specific `HardwareInterface*`;
3. exports the command and state interfaces expected by the mobile base controller;
4. publishes controller-side joint commands on `bridge/joint_state_command`;
5. subscribes to joint feedback on `bridge/joint_state_feedback`;
6. updates the exported state interfaces from the received feedback.

Robot-specific hardware packages that need direct access to the low-level controller can derive from `HardwareSystemInterface<HardwareInterface>`, select the appropriate `HardwareInterface*`, and implement their own `read()` and `write()` methods.

### 4.3) Exported plugins

The exported plugins are:

| Plugin | Hardware interface |
|---|---|
| `romea_mobile_base_hardware/GenericHardwareSystemInterface2FWS4WD` | `HardwareInterface2FWS4WD` |
| `romea_mobile_base_hardware/GenericHardwareSystemInterface4WS4WD` | `HardwareInterface4WS4WD` |
| `romea_mobile_base_hardware/GenericHardwareSystemInterface2THD` | `HardwareInterface2THD` |

Only these generic plugins are currently exported in `plugins.xml`. Other architecture-specific hardware interfaces are available as C++ classes and can be used by dedicated hardware or simulation packages.

## 5) Relation with other mobile base packages

`romea_mobile_base_hardware` is the hardware abstraction layer of the mobile base stack:

* `romea_mobile_base_description` defines the links, joints and `<ros2_control>` descriptions used to instantiate the hardware plugin;
* `romea_mobile_base_utils` provides helpers used to read `hardware_interface::HardwareInfo` and to build joint command/state handles;
* `romea_mobile_base_controllers` writes commands to the exported command interfaces and reads feedback from the exported state interfaces;
* `romea_mobile_base_simulation`, `romea_mobile_base_gazebo` and `romea_mobile_base_gazebo_classic` reuse the same hardware interface conventions for simulation;
* robot-specific hardware packages extend this package to communicate with the physical platform.
